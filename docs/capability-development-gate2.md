# Gate 2 public source/lifecycle contracts

Gate 1 remains intact. `standard/candidates.py` adds interoperable source-package,
dependency, generation, verification-environment, preview and lifecycle receipts.
The private product supplies generation/planning policy, kernel isolation and
review control. No World Kernel concept, public registry or compiler is replaced.

`CandidateSourcePackage` binds all UTF-8 source/document bytes to the existing
manifest, which remains `execution_eligible=false`. It requires implementation,
tests and documentation; canonical relative paths, bounded files/bytes, a declared
module/function entry point, exact dependency locks and generation attribution.
No archive extraction, native binary or executable installation is supported.
The private execution adapter supports JSON variables with explicit dimensions,
units and full floating-point values through the existing xarray plugin protocol.
Shared input dimension coordinates remain attached to output Fields.

`CodingAgent.generate(CandidateGenerationRequest)` is provider-neutral. It receives
the original typed plan and permitted dependency locks, not scientific arrays or
production context. Provider metadata are recorded assertions, not independently
authenticated attribution. Fixture replay is labeled `offline_fixture` and does
not demonstrate autonomous generation. A provider may return arbitrary new source
for a reviewed plan without adding task branches to the orchestrator.

`CandidateVerificationBundle` binds the package, plan, original verification
receipt, numerical invocation details and exact isolation environment. The
existing verification requirement kinds gain `syntax` and `security`; the six
Gate 1 mandatory kinds and original acceptance checks remain required. No
passing import, generated unit test or metadata report authorizes execution.

`CandidateLifecycleRecord` documents append-only versioned transitions:

```text
proposed -> generated -> tested -> verified -> approved -> active
```

Each record has request/source/evidence identities and a predecessor hash. Failed
verification stays at `tested`; unapproved candidates cannot progress. `active`
can describe only isolated execution in a fresh offline-review registry at this
gate. Records and `CandidateApproval` are nonauthorizing interoperability
receipts, not authentication or commercial/scientific admission mechanisms.

Production/API source execution stays disabled. Neither a lifecycle record nor
an approval JSON file makes source callable in the production World runtime.
Public code imports no private runner or intelligence. Public conformance and
offline contract tests remain independently runnable.

The private Gate 2 review documents the tested Linux isolation, two different
computational examples, source hashes, results, failures and limitations. A local
coding-provider trial is recorded separately from fixture replay; only independently
passing candidates count as verified. An autonomous natural-language Studio
development journey has not been exercised. Existing production dependency pins remain unchanged; a reviewed
public commit/pin update is required before independently installed release CI.
