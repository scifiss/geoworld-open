# Gate 2B generic generation and repair receipts

The existing source-package, development-plan, lifecycle and verification contracts
remain intact. New generic types in `standard/candidates.py` define a bounded
source-only provider response, attempt/token budgets, classified failure diagnoses
and predecessor-linked immutable attempt receipts. They grant no activation or
scientific permission and contain no private generation/planning implementation.

The coding response contains only Python source. A private host can supply package
formatting, fixed interface names, source hashes, dependency locks, documentation
and metadata transport while preserving generated numerical bytes. Helpers are
optional. Existing package requirements for tests/documentation remain; these can
be host-owned. Independent mathematical verification stays outside generated code.

Attempt receipts bind candidate/request/package identities to saved evidence and
explicitly keep execution unauthorized. Budgets permit at most three attempts;
verified receipts cannot contain unresolved failures. The private product owns
AST policy, provider prompts, repair decisions, isolation and scientific oracles.
No World Kernel records or production/client routes change.

The private feature branch must pin the exact reviewed public contract commit.
Contracts and their tests remain independently runnable. Feature-branch publication
does not authorize package publication, candidate activation or deployment.
